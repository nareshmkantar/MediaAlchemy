Group 1 Union / stack (same schema)

ID Scenario Input Expected Checks
1.1 Perfect union File A through 26th; File B from 27th; same schema Stack rows; no structural transform Row count = A + B; no unintended dupes; columns aligned
1.2 Overlapping dates A has 6/26, 6/27; B has 6/27, 6/28 Union allowed; warn that date/channel/publisher keys may duplicate Either keep dupes or apply explicit de-dupe rule — behaviour documented
1.3 Column order differs Same columns, shuffled order (e.g. publisher before date) Align by column name; safe union Stable mapping; no column drift
1.4 Missing column in one file File B missing impressions Union OK; missing cells NULL (or explicit fill rule) Schema union; no row drop

Group 2 Merge / join (different schema)

ID Scenario Input Expected Checks
2.1 Lookup metadata Sheet 1: metrics; Sheet 2: publisher → region Join on publisher; new column(s) Cardinality sane; region populated where key matches
2.2 Multi-key join Keys: date + channel + publisher Inner or left join per policy; horizontal expansion Key coverage; NULLs only where policy allows
2.3 Partial key match Some publishers missing from lookup Left join: NULL for misses; no silent row loss Unmatched count surfaced
2.4 Wrong join (AI / planner) Two sheets, same grain and same metric columns Recommend union, not join Critical: no artificial key join that duplicates metrics

Group 3 Duplicates and overlaps

ID Scenario Input Expected Checks
3.1 Exact duplicates Two identical rows (same date, publisher, channel, metrics) Detect; optional remove or aggregate per policy User or config chooses outcome; deterministic
3.2 Near duplicates Same keys, different metric values Flag conflict; do not auto-merge silently Review state or error surfaced
3.3 Duplicates after union A + B produces duplicate keys Warn: combined set contains duplicate rows Message references natural key used

Group 4 Partial match / column mismatch

ID Scenario Input Expected Checks
4.1 Extra column in one file File B adds campaign_name Union; new column; NULL in other file’s rows Wider schema; no row explosion
4.2 Same meaning, different names publisher_name_paid_media vs publisher Semantic / fuzzy mapping; align then union Mapping confidence or review for low confidence
4.3 Different dimension values Channel values differ across files (valid business data) Union; values are data, not schema conflict No false “error” on value diversity alone
4.4 Unrelated schemas Media metrics vs finance ledger Suggest keep separate No forced combine; explain why

Group 5 Multi-sheet / multi-file patterns

ID Scenario Input Expected Checks
5.1 Monthly sheets Sheet1 = Jan, Sheet2 = Feb, same layout Union (stack) Optional month column derivable
5.2 Country split File A UK, File B US, same metrics Union; ideally add country column No duplicate column semantics
5.3 Repeated tables in one sheet Two blocks same headers in one worksheet Stack (layout-level merge of blocks) Row order preserved or documented
5.4 Mixed relevant + irrelevant sheets Data + Pivot + Notes Include only data sheets; ignore pivots/notes Sheet selection explicit or explainable

Group 6 Bad data / conflict / failure

ID Scenario Input Expected Checks
6.1 Different granularity File A daily, File B weekly No automatic union without roll-up rule Clear grain mismatch message
6.2 Date format mismatch 6/26/2023 vs 2023-06-26 Normalize; then union Parsed dates equal where same calendar day
6.3 Type mismatch Cost numeric in A, text in B Cast or coerce with warnings Failed parses reported with row hints
6.4 Missing join keys Join requested but key column absent Block auto-join; require user input / mapping No silent Cartesian product

Decision rules (typical ingestion behaviour)

Operation When it applies
Union Same grain; same or mappable columns; independent rows; append vertically
Join Additional attributes from another table; stable key relationship; horizontal enrich
Keep separate Different business meaning; incompatible grain; no safe relationship
Stack (layout) Same physical table repeated in one sheet — internal extract then append
Tests should assert decision correctness and output shape (row counts, keys, NULL policy), not only that a particular tool was called.
